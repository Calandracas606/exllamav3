# ROCm gfx1100 v2 Refactor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refactor the existing `rocm-gfx1100` branch from the v1 "polyfill-and-hipify" strategy to the v2 "route around CUDA" strategy — removing polyfill files (compat.cuh, ptx.cuh stubs), excluding unused C++ kernels from the ROCm build, and routing Category A kernels to PyTorch native ops, while preserving all verified-working runtime routing.

**Architecture:** The v2 strategy classifies every C++ kernel into four categories: (A) replace with PyTorch native at Python level, (B) keep with minimal `#ifdef` guards, (C) exclude from ROCm build entirely, (D) Triton fallback. The refactoring is done incrementally: first add Python routing and source filtering so excluded kernels aren't needed, then strip the now-dead polyfill artifacts. The build stays working at every step.

**Tech Stack:** PyTorch (ROCm 7.14 wheels), HIP/clang 22, flash-linear-attention (Triton), uv for dependency management, gfx1100 (AMD Radeon RX 7900 XTX, RDNA3, wave32).

## Global Constraints

- All Python execution via `uv run --env-file .env python ...` (the `.env` sets ROCM_HOME for venv-local ROCm)
- gfx1100 is wave32 architecture. HIP's `__shfl_*_sync` requires 64-bit masks regardless (API quirk). The `exl_shfl_*` wrappers in `util.cuh` handle this.
- No weight caching: EXL3 forward must dequantize on-the-fly every call via `reconstruct_hgemm()`. Never cache dequantized fp16 weights (would balloon 6GB → 18GB).
- Never edit `_hip.cpp` / `_hip.cuh` / `.hip` files — these are auto-generated by PyTorch's hipify at build time. Edit `.cu` / `.cuh` / `.cpp` sources directly.
- CUDA build paths must not break: all ROCm logic behind `#ifdef USE_ROCM` / `if torch.version.hip:` guards only.
- Strict TDD: each change verified by build + tests before proceeding.
- `compat.cuh` and `ptx.cuh` ALREADY EXIST on master. Master's `compat.cuh` is 32 lines (just `tanh_opt` + `copysignf_pos`). Master's `ptx.cuh` has real PTX tensor-core intrinsics. The v1 branch bloated both. The cleanup phase reverts to master and adds back only what's needed.

## Task 1: Route RMS Norm to PyTorch Native on ROCm

**Files:**
- Modify: `exllamav3/modules/rmsnorm.py` (forward method, ~line 99)
- Modify: `exllamav3/modules/gated_rmsnorm.py` (forward method, ~line 117)

**Interfaces:**
- Produces: `RMSNorm.forward()` and `GatedRMSNorm.forward()` dispatch to `forward_torch()` when `torch.version.hip` is set, instead of calling `ext.rms_norm` / `ext.gated_rms_norm`

**Rationale:** Both modules already have `forward_torch()` methods that compute RMS norm in pure PyTorch. The `forward()` methods currently always call `ext.rms_norm`. On ROCm, we route to `forward_torch()` instead. This makes the C++ `norm.cu` unnecessary on ROCm (excluded from build in Task 5).

- [ ] **Step 1: Modify RMSNorm.forward() to route to forward_torch on ROCm**

In `exllamav3/modules/rmsnorm.py`, add a ROCm guard at the top of `forward()`:

```python
    @override
    def forward(
        self,
        x: torch.Tensor,
        params,
        out_dtype: torch.dtype | None = None,
        residual: torch.Tensor | None = None,
        residual_in: torch.Tensor | None = None,
    ) -> torch.Tensor:
        # ROCm: route to PyTorch native. The C++ norm kernel is excluded from the ROCm build.
        # forward_torch doesn't support fused residual paths, so handle residual in PyTorch.
        if torch.version.hip:
            if residual_in is not None:
                residual_in.add_(x)
                return self.forward_torch(residual_in, params, out_dtype)
            if residual is not None:
                return self.forward_torch(residual, params, out_dtype)
            return self.forward_torch(x, params, out_dtype)

        dtype = out_dtype or self.out_dtype
        # ... rest of existing forward unchanged
```

- [ ] **Step 2: Modify GatedRMSNorm.forward() to route to forward_torch on ROCm**

In `exllamav3/modules/gated_rmsnorm.py`, add ROCm guard:

## Task 2: Route GatedMLP Activations to PyTorch Native on ROCm

**Files:**
- Modify: `exllamav3/modules/mlp.py` (GatedMLP class, activation dispatch ~line 588)

**Interfaces:**
- Produces: `GatedMLP.activation_fn_call` dispatches to a PyTorch-native closure when `torch.version.hip` is set, instead of `ext.silu_mul` / `ext.gelu_mul` / `ext.relu2_mul`

**Rationale:** The C++ activation kernel computes `z = activation(x) * y` with optional softcap clamping (`z = clamp(z, -act_limit, act_limit)`). The non-gated `MLP` class already uses pure PyTorch activations (`F.silu`, `F.gelu`, etc.). The `GatedMLP` class uses `ext.silu_mul` etc. We need PyTorch equivalents for the fused `activation(x) * y` + softcap pattern.

- [ ] **Step 1: Add PyTorch-native gated activation helpers to GatedMLP**

In `exllamav3/modules/mlp.py`, in the `GatedMLP.__init__` method (around line 588), replace the activation dispatch:

```python
        match activation_fn:
            case "silu": self.activation_fn_call = ext.silu_mul
            case "relu2": self.activation_fn_call = ext.relu2_mul
            case "gelu": self.activation_fn_call = ext.gelu_mul
```

with:

```python
        if torch.version.hip:
            # ROCm: use PyTorch-native gated activation. Computes z = act(x) * y
            # with optional softcap clamping, matching the C++ kernel semantics.
            def _torch_act_mul(act_fn):
                def fn(x, y, z, act_limit):
                    result = act_fn(x) * y
                    if act_limit != 0.0:
                        result = torch.clamp(result, min=-act_limit, max=act_limit)
                    z.copy_(result)
                return fn
            match activation_fn:
                case "silu": self.activation_fn_call = _torch_act_mul(F.silu)
                case "relu2": self.activation_fn_call = _torch_act_mul(lambda x: torch.square(F.relu(x)))
                case "gelu": self.activation_fn_call = _torch_act_mul(lambda x: F.gelu(x, approximate="tanh"))
        else:
            match activation_fn:
                case "silu": self.activation_fn_call = ext.silu_mul
                case "relu2": self.activation_fn_call = ext.relu2_mul
                case "gelu": self.activation_fn_call = ext.gelu_mul
```

// ============================================================================
// ROCm polyfills needed by Category B kernels (reconstruct, hadamard, hgemm)
// ============================================================================

#if defined(USE_ROCM)

#include <hip/hip_runtime.h>

// HIP does not provide __dp4a; emulate via byte extraction + multiply-accumulate.
// Used by codebook.cuh (reconstruct.cu, pack.cu dependency chain).
__device__ __forceinline__ int __dp4a(uint32_t a, uint32_t b, int c)
{
    int result = c;
    #pragma unroll
    for (int i = 0; i < 4; i++)
    {
        int8_t va = (int8_t)((a >> (i * 8)) & 0xFF);
        int8_t vb = (int8_t)((b >> (i * 8)) & 0xFF);
        result += va * vb;
    }
    return result;
}

__device__ __forceinline__ uint32_t __dp4a(uint32_t a, uint32_t b, uint32_t c)
{
    return (uint32_t)__dp4a(a, b, (int)c);
}

// HIP provides __hmax2/__hmin2 for bfloat162 but NOT for half2.
// Used by hadamard_inner.cuh.
__device__ __forceinline__ half2 __hmax2(half2 a, half2 b)
{
    return __halves2half2(__hmax(__low2half(a), __low2half(b)),
                          __hmax(__high2half(a), __high2half(b)));
}

__device__ __forceinline__ half2 __hmin2(half2 a, half2 b)
{
    return __halves2half2(__hmin(__low2half(a), __low2half(b)),
                          __hmin(__high2half(a), __high2half(b)));
}

// HIP's hipFuncSetAttribute requires const void* but CUDA's accepts function pointers.
// Used by cuda_drv.cpp / hip_drv.cpp.
template <typename T>
__host__ inline hipError_t hipFuncSetAttribute(T fn, hipFuncAttribute attr, int val)
{
    return ::hipFuncSetAttribute(reinterpret_cast<const void*>(fn), attr, val);
}

#endif // USE_ROCM
